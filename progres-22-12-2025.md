# Laporan Progres Kerja: Proyek Utero Cloud (22 Desember 2025)
**Dokumen ini merangkum status proyek setelah refaktorisasi arsitektur besar dari monolith Next.js ke arsitektur Frontend-Backend terpisah yang siap untuk hosting di VPS.**

---

## 1. Papan Skor Proyek: Perbandingan Rencana Awal vs. Realita

### ✅ Sesuai Rencana & Sudah Selesai

*   **Autentikasi Pengguna, Peta Interaktif, Dashboard Admin:** Fitur-fitur inti ini tetap berfungsi dan matang.

*   **[PEMBARUAN ARSITEKTUR] Migrasi ke Backend Terpisah (NestJS):**
    *   **Pembuatan Server Backend NestJS:** Sebuah server backend baru yang kuat dan terstruktur telah dibuat di direktori `backend/` menggunakan NestJS. Server ini sekarang bertanggung jawab atas semua logika bisnis, koneksi database, dan akan menangani komunikasi real-time.
    *   **Pemisahan Frontend & Backend:** Arsitektur proyek telah diubah secara fundamental. Proyek Next.js sekarang berfungsi murni sebagai **frontend**. Semua pengambilan data (termasuk di halaman utama) tidak lagi mengakses database secara langsung, melainkan melakukan `fetch` ke API yang disediakan oleh server backend NestJS.
    *   **Konsolidasi Server:** Kebutuhan akan `chat-server` terpisah telah **dihilangkan**. Logika Socket.IO akan digabungkan ke dalam server backend utama, menyederhanakan alur kerja pengembangan dan deployment secara signifikan.

*   **[PEMBARUAN STABILITAS] Lingkungan Pengembangan Lokal (Docker):**
    *   **Implementasi Database Lokal:** Proyek sekarang berjalan di atas database **PostgreSQL** yang dijalankan secara lokal melalui **Docker**.
    *   **Penyelesaian Masalah Koneksi:** Semua masalah konektivitas database yang sebelumnya menghambat (error `P1001`, `P1013`, masalah IPv4/IPv6 Supabase) telah **teratasi sepenuhnya**. Lingkungan pengembangan sekarang jauh lebih cepat, stabil, dan tidak bergantung pada koneksi internet.
    *   **Migrasi & Seeding Berhasil:** Skema database telah berhasil **dimigrasikan** ke database PostgreSQL lokal, dan data *dummy* awal telah berhasil di-*seed*, memungkinkan pengembangan untuk dilanjutkan.

### ⚠️ Sesuai Rencana tapi Berubah / Belum Lengkap

*   **Database: Siap Produksi.**
    *   **Status:** Proyek sekarang berjalan di PostgreSQL via Docker. Migrasi ke database online (Supabase/Neon/VPS) untuk *deployment* sekarang menjadi sangat mudah, hanya masalah mengubah `DATABASE_URL` di file `.env` backend. **Bloker pengembangan ini telah teratasi.**

*   **File Storage (Cloud Storage):**
    *   **Status Saat Ini:** **GAP KRITIS #1.** Proyek masih menggunakan penyimpanan lokal. Ini adalah *blocker* utama terakhir yang mencegah website untuk *go-live*.

*   **Refaktorisasi Frontend (Dalam Proses):**
    *   **Status:** Baru halaman utama (`/`) yang telah diubah untuk mengambil data dari backend NestJS. Halaman-halaman lain (detail billboard, dashboard admin, proses checkout, dll.) **masih menggunakan Prisma secara langsung** dan perlu diperbarui.

*   **Fitur Lupa Password & Fungsionalitas Lainnya:**
    *   Status fitur-fitur ini tidak berubah dan masih perlu diimplementasikan.

## 2. Rangkuman Kekurangan (GAP Analysis)

Daftar kekurangan telah diperbarui secara signifikan setelah refaktorisasi.

### 1. Kekurangan Kritis (Blocker Deployment)

*   **Tidak ada Cloud Storage:**
    *   **Masalah:** Semua fitur upload gambar akan gagal total saat di-hosting online.
    *   **Prioritas:** **#1 - Sangat Mendesak.**

*   **Frontend Belum Sepenuhnya Terpisah:**
    *   **Masalah:** Sebagian besar aplikasi frontend masih mencoba terhubung ke database secara langsung, yang akan gagal di lingkungan produksi dan melanggar arsitektur baru.
    *   **Prioritas:** **#2 - Sangat Mendesak.**

### 2. Kekurangan Fungsionalitas User

*   **Tidak ada Payment Gateway:**
    *   **Prioritas:** **#3 - Tinggi.**
*   **Tidak ada Fitur Lupa Password.**
*   **Link Email Masih `localhost`.**

## 3. Kesimpulan & Rencana Selanjutnya

**Kesimpulan:** Proyek Utero Cloud telah berhasil melewati **refaktorisasi arsitektur yang paling sulit dan paling penting**. Dengan beralih ke backend terpisah dan database lokal via Docker, kita telah menyelesaikan semua masalah konektivitas dan membangun fondasi yang kokoh dan skalabel yang siap untuk di-hosting di VPS.

Fokus sekarang bergeser dari perbaikan fondasi ke penyelesaian migrasi arsitektur di level frontend dan menutup celah kritis terakhir.

**Prioritas Pengerjaan:**
1.  **Selesaikan Refaktorisasi Frontend:** Ubah semua halaman dan komponen yang tersisa (detail billboard, admin, checkout) agar mengambil datanya dari API backend NestJS, bukan dari Prisma secara langsung.
2.  **Integrasi Cloud Storage (Cloudinary):** Setelah frontend sepenuhnya terpisah, implementasikan upload file ke Cloudinary melalui backend.
3.  **Implementasi Payment Gateway (Xendit):** Hubungkan alur pembayaran ke backend.
4.  Menyempurnakan fitur fungsional lainnya (Lupa Password, dll).
